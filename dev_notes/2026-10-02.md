# 2026-10-02 — WebSocket bridge: state never arrives

## Intent
Fix repeated `state_timeout` despite user in active New Game (WS connects, Step:0, no `DIAG`/`Spawn` in logger.txt).

## Hypothesis
- Python `websockets` 17 defaults (`compression=deflate`, ping every 20s) may not interoperate with pollnet; Lua gates all state sends on `socket:status() == "open"`.
- If pollnet never reaches `open`, Python sees a connected client but zero JSON messages.

## Planned changes
1. `noita_env.py`: `compression=None`, disable WS ping; send noop action immediately on connect.
2. `init.lua`: connect to `127.0.0.1`; drain polls while `opening`; periodic WARN for stuck status / missing player.

## Expected outcome
First live state within seconds of in-world connect; train reaches "starting PPO"; logger shows `Spawn recorded` or `DIAG`.

## Applied
- `noita_env.py`: WS server without deflate/ping; noop action on connect.
- `init.lua`: `127.0.0.1`, opening-state drain, WARN every ~5s if stuck.

## Outcome
Pending user retest with `train.py --fresh`.

## Follow-up (same day)
User in surface New Game still Step:0 — not a “wait for more game” issue on Python side.
- Root cause: mod required `socket:status() == "open"` before any state send; pollnet can stay `"opening"` while WS works.
- Fix: `socket_usable()` allows sending when not error/closed; safe `get_player_entity()`; DIAG every 3s in logger; clearer train.py message.

## Logger evidence (10:15 run)
`DIAG ws st=open player=yes ep=0 step=0` repeating — bridge up, player in world, but no JSON reached Python.
- Cause: action frames gated on `GameGetFrameNum() % 4`; frame counter can stall while post-update still runs.
- Fix: `bridge_tick` for FRAME_SKIP; always run pipeline while `episode_steps == 0`; pcall on CharacterDataComponent; log `State sent to Python`; poll after send; Python logs first JSON receipt.

## Root cause (10:21 logger)
`DIAG ... tick=1869 step=0` — pipeline entered but never completed. **`read_spawn_override()` was called but never defined** → Lua error every frame at first spawn setup (silent in-game). Added `read_spawn_override()` reading optional `spawn.txt`; pcall on DamageModel/Wallet components.
